# 05 — MVP และแผนพัฒนา 🗺️

> ⚠️ กับดักใหญ่ที่สุดของคนทำเกมคนเดียวคือ**คิดระบบเยอะเกินจนทำไม่เสร็จ**
> ให้ทำเวอร์ชันเล็กที่สุดที่เล่นแล้วสนุกให้ได้ก่อน แล้วค่อยเพิ่มระบบอื่น

## 🎯 คำถามเดียวที่ MVP ต้องตอบ
> **"แค่ตกปลาอย่างเดียว สนุกไหม? อยากเล่นต่อไหม?"**

ถ้ามินิเกมตกปลาไม่สนุก ระบบอื่นที่ใส่เพิ่มก็ช่วยไม่ได้

---

## ระยะที่ 0 — ต้นแบบมินิเกม (1–2 สัปดาห์)
- [ ] เหวี่ยงเบ็ด → รอปลากิน → ดึงปลาด้วยแถบแรงตึง
- [ ] ปลา 5 ชนิด นิสัยการดิ้นต่างกัน
- [ ] ระดับความหายาก 3 ระดับ พร้อมเอฟเฟกต์ตอนได้ปลา
- [ ] ให้เพื่อน 3–5 คนลองเล่น แล้วถามว่าสนุกไหม

## ระยะที่ 1 — MVP (1–2 เดือน)
- [ ] เมือง 1 แห่ง ทำเล 3 จุด
- [ ] เรือ 1 ลำ อัปเกรดได้ 3 ขั้น
- [ ] เบ็ด 3 อัน ม็อด 5 แบบ
- [ ] ปลา 15 ชนิด และปลาตำนาน 1 ตัว
- [ ] ขายปลา ซื้อของ และเซฟเกม
- [ ] สารานุกรมปลา
- [ ] ระบบ run: น้ำมันจำกัด สุ่มทำเล และตัดสินใจว่าจะกลับฝั่งเมื่อไร

## ระยะที่ 2 — เดโม (2–3 เดือน)
- [ ] เมืองที่ 2 พร้อมเรือลำที่ 2
- [ ] ของบัฟชั่วคราว 15–20 ชิ้น
- [ ] เหตุการณ์สุ่มกลางทะเล
- [ ] สเตตัสตัวละคร
- [ ] ปล่อยเดโมบน itch.io / Steam Next Fest

## ระยะที่ 3 — เกมเต็ม
- [ ] 4–5 เขต ปลา 80–100 ชนิด
- [ ] ลูกเรือ ฤดูกาล และข้างขึ้นข้างแรม
- [ ] เนื้อเรื่องและบอสพญานาค 🐉
- [ ] วางขายบน Steam

---

## 🛠️ เทคโนโลยีที่แนะนำ
| เรื่อง | ทางเลือก | เหตุผล |
|---|---|---|
| Engine | **Godot 4** | ฟรี เบา เหมาะกับเกม 2D ส่งออกได้ทั้ง PC มือถือ และเว็บ |
| ภาษา | GDScript | ไวยากรณ์คล้าย Python เรียนง่าย |
| ภาพ | Pixel Art 2D | คนเดียวทำได้ และเข้ากับแนวเกม |
| เก็บข้อมูลเกม | ไฟล์ JSON / Resource | แก้ข้อมูลปลา เบ็ด และเรือได้โดยไม่ต้องแก้โค้ด |

## 📁 โครงสร้างโปรเจกต์ (เมื่อเริ่มเขียนโค้ด)
```
fishing-roguelite/
├─ docs/            # เอกสารออกแบบ (ไฟล์ชุดนี้)
├─ game/            # โปรเจกต์ Godot
│   ├─ scenes/      # ฉากต่างๆ: เมือง ทะเล มินิเกม
│   ├─ scripts/     # โค้ด
│   ├─ data/        # ข้อมูลปลา เบ็ด เรือ ม็อด (JSON)
│   └─ assets/      # ภาพ เสียง
└─ README.md
```
